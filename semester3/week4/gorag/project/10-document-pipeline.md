# 10 文档处理管线

## 任务目标

负责 `docs` 中 Markdown/TXT 文件从磁盘到结构化 Chunk 的纯文档处理过程。该工作包不调用 Embedding，不写数据库。

主要代码区域：

```text
internal/document/loader
internal/document/cleaner
internal/document/splitter
```

## 输入与输出

- 输入：`docs` 根目录、单文件大小限制、切分参数。
- 输出：文档元数据、清洗后的内容和有序 Chunk。
- 源文件路径始终保存为相对于 `docs` 的路径。
- Chunk 数据契约见 [`00-shared-context.md`](00-shared-context.md#跨模块数据契约)。

## 文档扫描与加载

1. 递归扫描 `docs` 目录。
2. 只接受 `.md` 和 `.txt` 文件，忽略其他文件类型。
3. 跳过空文件和非法 UTF-8 文件。
4. 限制单个文件大小。
5. 保存相对于 `docs` 的文件路径。
6. 计算文件 SHA-256，用于判断内容是否变化。

## 文档清洗

1. 去除 UTF-8 BOM。
2. 将不同换行符统一为 LF。
3. 压缩过多的连续空行。
4. 去除首尾空白。
5. 可选择解析 Markdown Front Matter。
6. 去除无意义的 HTML 注释。
7. 保留标题、列表、表格和代码块。

## Markdown 切分

1. 优先按照标题层级切分，并保存完整标题路径。
2. 章节过长时按段落继续切分。
3. 段落过长时按句子继续切分。
4. 尽量不在代码块内部切分。
5. 不在不同标题章节之间添加重叠。

## TXT 切分

按以下优先级逐级切分：

1. 空行。
2. 换行。
3. 中文句号和问号。
4. 英文句号。
5. 固定长度。

## 初始切分参数

| 参数 | 初始值 |
|---|---|
| 目标大小 | 800–1200 个字符 |
| 最大大小 | 1600 个字符 |
| 重叠大小 | 100–150 个字符 |
| 最小大小 | 100 个字符 |

这些参数需要可配置，并由评测数据进一步调整。短小但语义完整的独立章节不应仅为了满足最小大小而与其他标题章节混合。

## 边界与依赖

- 向下只依赖文件系统和标准文本处理能力。
- 向上为 indexer 提供稳定的扫描、加载和切分接口。
- 不负责判断新建/更新/删除，也不负责文档版本切换。
- 不负责 Embedding、数据库写入或检索。

## 完成标准

- 能正确加载合法的 Markdown/TXT，并拒绝空文件、超限文件和非法 UTF-8。
- Markdown 标题层级、列表、表格和代码块语义得到保留。
- Chunk 不超过最大大小，并正确记录顺序、标题路径和起止行号。
- 文件及 Chunk 哈希结果稳定；相同输入重复处理得到相同结果。
- 测试覆盖换行/BOM、深层标题、超长段落、代码块、中文/英文分隔符和边界大小。
