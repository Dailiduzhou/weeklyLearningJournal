# 60 测试与评测

## 任务目标

建立单元测试、pgvector 集成测试和知识库问答评测集，验证正确性、失败安全性和拒答能力，并用结果调整切分与检索参数。

主要区域：

```text
internal/**/**/*_test.go
testdata/evaluation.jsonl
```

测试技术：

- Go `testing`。
- Testcontainers Go。
- PostgreSQL pgvector 测试容器。

## 评测数据

至少编写五个能从知识库中找到答案的问题。另外增加以下类型：

- 知识库外问题。
- 同义改写问题。
- 表述模糊问题。
- 跨章节问题。
- 删除文档后的问题。
- 重新索引后的问题。

每个测试用例至少保存：

- 问题。
- 是否应该回答。
- 预期来源文件。
- 预期标题章节。
- 答案关键字。

建议 `evaluation.jsonl` 每行一个独立 JSON 对象，便于追加用例和逐项报告结果。

## 必须验证的行为

1. 文档能够正确加载。
2. Markdown 标题层级能够保留。
3. Chunk 大小符合限制。
4. 重复同步不会重复入库。
5. 修改文件后能够生成新版本。
6. 删除文件后不能继续检索。
7. 正确问题能够命中预期来源。
8. 知识库外问题能够拒答。
9. 返回引用确实属于本次检索结果。
10. Context 取消和超时能够生效。

## 测试分层

### 单元测试

- 清洗、切分、哈希和标题路径。
- 相似度过滤、来源编号和引用解析/校验。
- HTTP 请求校验与响应映射。
- 使用 fake 接口验证失败和 Context 取消，不依赖真实远程模型。

### 数据库集成测试

- 自动迁移和 pgvector 扩展。
- 唯一约束、版本切换和删除过滤。
- 精确 Cosine 检索排序。
- 失败回滚和重复同步幂等性。

### 端到端评测

- 使用 `docs`、固定 Embedding/回答模型配置和 `evaluation.jsonl`。
- 报告可回答准确性、拒答正确性、来源命中情况。
- 根据结果调整 Chunk 参数、Top K 和相似度阈值，而不是只凭单个问题调参。

## 边界与协作

- 各功能工作包负责自己的单元测试和基础集成测试。
- 本工作包负责共享 fixture、Testcontainers 基础设施、评测数据格式和端到端执行器。
- 测试不得依赖执行顺序；每个用例隔离数据库状态。

## 完成标准

- 至少五个知识库内问题及建议的负向/生命周期场景已进入评测集。
- 十项必须验证的行为都有自动化覆盖。
- 集成测试能在干净环境创建并销毁 pgvector 数据库。
- 评测输出能定位失败问题及其预期/实际来源。
- 项目记录最终采用的 Chunk、Top K 和相似度阈值参数。
