# 30 索引生命周期

## 任务目标

编排文档管线、Embedding 和仓储，实现可重复、失败安全的同步、指定文件索引、删除和重建。

主要代码区域：

```text
internal/indexer
cmd/indexer
```

## 支持的操作

- 同步全部文档。
- 索引指定文件。
- 删除指定文档。
- 重新索引指定文档。
- 重新索引全部文档。

## 同步索引流程

1. 扫描 `docs` 目录。
2. 计算每个文件的内容哈希。
3. 新文件执行新增索引。
4. 哈希未变化的文件直接跳过。
5. 哈希变化的文件执行重新索引。
6. 数据库存在但磁盘不存在的文件标记为删除。
7. 记录本次索引任务及处理结果。

## 单文档重新索引流程

1. 计算待写入的新文档版本。
2. 加载、清洗并切分文档。
3. 在事务外批量生成新版本的所有向量。
4. 将新版本 Chunk 写入数据库。
5. 确认所有 Chunk 成功写入。
6. 在短事务中切换当前有效版本。
7. 切换成功后清理旧版本数据。

## 一致性与失败语义

- Embedding 请求不能放在数据库长事务中。
- 加载、切分、Embedding 或写入任何一步失败时，继续保留旧版本。
- 在新版本完整可用之前，不修改当前有效版本。
- 重复执行同步命令不能产生重复 Chunk。
- 删除操作标记数据库文档状态，使其立即退出检索；物理清理由仓储策略处理。
- `index_runs` 必须记录任务类型、状态、计数、时间和错误信息。
- 单文件失败不应丢失其旧版本；整次任务的最终状态应准确反映部分失败。

## CLI 边界

`cmd/indexer` 只负责：

- 解析命令、目标文件和配置。
- 创建依赖并传递 Context。
- 调用 `internal/indexer` 用例。
- 输出结构化日志并设置合理的退出码。

业务规则保留在 `internal/indexer`，不能只存在于 CLI 层。

## 依赖

- 文档扫描、加载、清洗和切分：[`10-document-pipeline.md`](10-document-pipeline.md)。
- Embedding 和数据库原子操作：[`20-embedding-and-storage.md`](20-embedding-and-storage.md)。
- 该工作包不负责在线检索和回答生成。

## 完成标准

- 首次同步能够新增全部合法文档。
- 第二次无变化同步跳过所有文档且不产生重复 Chunk。
- 修改文件生成新版本，并仅在完整成功后切换。
- 重新索引失败时旧版本仍可检索。
- 从磁盘删除文件后，同步会标记删除且该文档不再可检索。
- 所有支持的操作都有 CLI 入口、清晰日志和自动化测试。
- Context 取消能停止后续工作并正确结束 `index_runs`。
