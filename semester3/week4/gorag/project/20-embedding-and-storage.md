# 20 Embedding 与存储

## 任务目标

实现 Ollama Embedding 客户端、PostgreSQL/pgvector 数据模型、迁移和仓储能力，为索引与检索提供稳定接口。

主要代码区域：

```text
internal/embedding
internal/repository
migrations
```

## Embedding 要求

- 文档和问题必须使用同一个模型：`qwen3-embedding:0.6b`。
- 输出向量维度固定为 1024。
- 文档向量按批次调用 Ollama。
- 批次大小和并发数量可配置并受控。
- 每次调用设置 Context 超时。
- 失败后只进行有限次数重试。
- 记录失败的文件和 Chunk。
- 任一 Chunk Embedding 失败时，上层不能切换该文档的有效版本。
- 问题向量可增加检索任务说明，告诉模型从后端学习知识库中检索可直接回答问题的片段。
- 文档正文不添加问题侧的检索任务说明。

## 数据库迁移

启用 PostgreSQL `vector` 扩展，并创建以下数据结构。

### `documents`

保存源文档信息：

- 文档标识。
- 唯一的源文件路径。
- 标题。
- 文件内容哈希。
- 当前有效版本。
- 文档状态。
- 创建时间、更新时间、索引完成时间。

### `document_chunks`

保存文档片段：

- Chunk 标识。
- 文档标识和文档版本。
- Chunk 序号、正文、标题路径。
- 起始行号、结束行号、内容哈希。
- Embedding 模型、Embedding 维度。
- 1024 维向量。
- 创建时间。

### `index_runs`

保存索引任务：

- 任务标识、任务类型、任务状态。
- 开始时间、完成时间。
- 处理文档数量、处理 Chunk 数量。
- 错误信息。

## 数据库约束

1. 源文件路径必须唯一。
2. 同一文档版本中的 Chunk 序号必须唯一。
3. 删除文档后不能继续参与检索。
4. 检索只查询文档的当前有效版本。
5. 存储的模型名、维度和向量列定义必须一致。

## 仓储能力边界

该工作包提供原子、可组合的数据操作，至少支持：

- 按相对路径读取或创建文档记录。
- 读取已知文档及其哈希、状态和当前有效版本。
- 写入一个新版本的全部 Chunk。
- 在短事务中校验并切换当前有效版本。
- 标记文档删除。
- 清理非有效旧版本。
- 创建并完成/失败一个 `index_runs` 记录。
- 使用 pgvector 执行带文档状态和有效版本约束的相似度查询。

索引流程编排属于 `30-index-lifecycle.md`，Top K 和阈值处理属于 `40-retrieval-and-rag.md`。

## 事务与错误约束

- Embedding 请求绝不位于数据库事务内。
- 批量写入失败必须回滚该批数据库变更。
- 版本切换使用短事务，并验证新版本已完整写入。
- 所有数据库和 Ollama 操作传播 Context 取消与超时。

## 完成标准

- 全新数据库可通过迁移启用 pgvector 并创建全部表、索引和约束。
- Embedding 客户端验证返回向量维度，支持批处理、并发限制、超时与有限重试。
- 仓储测试证明路径唯一、Chunk 序号唯一、删除过滤和当前版本过滤有效。
- 任何部分失败都不会把不完整版本暴露给检索。
- 通过 pgvector Testcontainers 集成测试验证迁移、读写和向量查询。
