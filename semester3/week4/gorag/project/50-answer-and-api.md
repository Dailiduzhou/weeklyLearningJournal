# 50 回答、引用与 HTTP API

## 任务目标

约束 ChatModel 只基于检索上下文作答，校验引用，实现统一拒答语义，并通过 HTTP 暴露问答和健康检查接口。

主要代码区域：

```text
internal/rag
internal/transport
cmd/server
```

## 回答约束

- 大模型只能根据提供的上下文回答。
- 每项关键结论必须引用来源编号。
- 不得使用未出现在上下文中的来源编号。
- 不得根据模型自身知识补充知识库中不存在的事实。

## 引用校验

回答生成后由程序校验：

1. 每个引用编号必须存在于本次检索上下文。
2. 可回答结果至少包含一个有效引用。
3. 输出中去除重复引用。
4. 不允许引用本次未检索到的文档。
5. 引用无效时将结果降级为无法回答。

成功响应的语义数据包括：

- 是否可以回答。
- 回答正文。
- 引用来源列表。
- 每个来源的源文件路径、标题层级、起止行号和相似度。

## 无法回答

满足以下任一条件时拒绝回答：

- 没有检索结果。
- 最高相似度低于阈值。
- 所有候选 Chunk 都被过滤。
- Embedding 调用失败。
- 数据库检索失败。
- 模型回答没有有效引用。

统一返回类似：

> 当前知识库中没有找到足够可靠的依据，暂时无法回答该问题。

拒答是正常的产品结果。内部依赖错误应记录日志；HTTP 状态码与响应体不能泄漏凭据或内部实现细节。

## API

### `POST /api/v1/questions`

请求内容：

```json
{
  "question": "问题文本"
}
```

响应的核心字段：

```json
{
  "answerable": true,
  "answer": "带来源编号的回答",
  "sources": []
}
```

每项 source 携带源文件路径、标题层级、起止行号和相似度。

### `GET /healthz`

提供进程存活检查。

### `GET /readyz`

提供服务就绪检查。依赖检查细节见 [`70-deployment-and-operations.md`](70-deployment-and-operations.md)。

## Server 边界

- 使用 Go 标准库 `net/http`。
- `cmd/server` 负责加载配置、组装依赖、启动/优雅关闭 HTTP 服务。
- server 不直接扫描或修改 `docs`；文档管理由 indexer 命令完成。
- transport 负责请求校验、JSON 编解码和 HTTP 映射，不承载 RAG 业务规则。

## 完成标准

- 有依据的问题返回回答和至少一个可追溯来源。
- 无结果、低相似度、依赖失败和无效引用均稳定拒答。
- 伪造、未知和重复来源编号由程序识别并处理。
- 问答、存活和就绪接口均有 handler 测试。
- 非法 JSON、空问题、超大请求和 Context 取消有明确行为。
- server 支持优雅关闭，且不包含 docs 写操作。
