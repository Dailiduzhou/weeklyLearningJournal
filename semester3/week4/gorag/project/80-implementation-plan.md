# 80 实施计划与协作边界

## 使用方式

本文件供主代理拆任务和安排依赖。每个 subagent 仍需先读 [`00-shared-context.md`](00-shared-context.md)，再读自己的工作包。

## 阶段计划

### 第一阶段：项目骨架与基础设施

- 建立项目目录。
- 建立 Docker Compose。
- 创建数据库迁移。

对应工作包：`20`、`70`。

### 第二阶段：文档管线

- 实现文档扫描。
- 实现 Markdown 和 TXT 加载。
- 实现文档清洗和切分。

对应工作包：`10`。

### 第三阶段：Embedding 与入库

- 接入 Ollama Embedding。
- 实现批量向量生成。
- 实现文档和 Chunk 入库。

对应工作包：`20`，依赖 `10` 的数据契约。

### 第四阶段：索引生命周期

- 实现增量同步。
- 实现删除文档。
- 实现文档版本切换。
- 实现全部重新索引。

对应工作包：`30`，依赖 `10` 和 `20`。

### 第五阶段：检索与 RAG

- 实现 `PgVectorRetriever`。
- 实现相似度过滤。
- 使用 Eino 组装 RAG Chain。

对应工作包：`40`，依赖 `20`。

### 第六阶段：回答与 API

- 实现回答引用。
- 实现引用校验。
- 实现无法回答机制。
- 暴露 HTTP API。

对应工作包：`50`，依赖 `40`。

### 第七阶段：评测与交付

- 编写知识库测试问题。
- 调整 Chunk 参数。
- 调整 Top K 和相似度阈值。
- 完成部署文档。

对应工作包：`60`、`70`；测试应从第一阶段起持续补充，而非最后集中编写。

## 推荐并行批次

```text
批次 A（可并行）
  A1: 10 文档管线
  A2: 20 数据库迁移与仓储接口
  A3: 70 Compose 基础设施

批次 B
  B1: 20 Ollama Embedding 与向量入库（依赖 A1/A2 契约）

批次 C（可并行）
  C1: 30 索引生命周期（依赖 A1/B1）
  C2: 40 检索骨架与 Context Builder（依赖 A2/B1）

批次 D
  D1: 50 回答、引用与 API（依赖 C2）

贯穿所有批次
  60 单元测试、集成测试和评测集
  70 配置、启动检查与最终联调
```

## Subagent 任务模板

分配任务时可直接使用：

```text
先阅读 project/00-shared-context.md 和 project/<工作包>.md。
只实现该工作包中明确列出的范围，并遵守“边界与依赖”。
完成后运行与修改范围相称的测试，并报告：
1. 修改文件；
2. 已满足的完成标准；
3. 测试命令及结果；
4. 未解决风险或需要其他工作包提供的接口。
```

## 集成纪律

- 并行任务先约定共享接口和数据结构，再分别实现。
- 不让多个 subagent 同时编辑同一个文件；共享入口文件由主代理统一集成。
- 跨包调用依赖接口，不直接耦合具体 SDK、SQL 或 HTTP 表示。
- 每个批次结束后运行全量已有测试，再开始下一个依赖批次。
- 如实现与需求冲突，先更新对应工作包并同步受影响的依赖方。
